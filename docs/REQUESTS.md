# 작업 요청
## 협업 규칙
시작할 때 최신 원격 변경을 확인한다. 미커밋 작업을 보존하고 충돌을 해결한다.
PLAN.md는 기획, REQUESTS.md는 요청, STATUS.md는 결과다.
GPT/Codex는 기획·검토, Claude Code는 구현을 맡는다.
같은 파일을 동시에 수정하지 않는다. 기획 변경 제안은 STATUS.md에 남긴다.
구현은 별도 브랜치와 검토 가능한 커밋/PR로 남긴다. main 강제 푸시와 자동 배포는 하지 않는다.
푸시/PR 권한이 없으면 로컬 결과와 필요한 조치를 기록한다.
문서 갱신은 상대 AI를 자동 실행하지 않는다. 사용자가 시작 요청을 한다.

## REQ-002: 블랙·화이트 + Google Sans 디자인 개선
상태: 구현 대기
담당: Claude Code
사용자 확정 요청(2026-10-04): 블랙·화이트 컬러 컨셉, Google Sans 폰트.
이 요청은 PLAN.md의 초기 강조색/시스템 폰트 기본값보다 우선한다.

### 시각 디자인
- 기존 검정 배경의 갤러리 구성을 유지하고 흰색 타이포그래피와 무채색으로 정리한다.
- 권장 토큰: 배경 #0A0A0A, 표면 #141414, 올라온 표면 #1C1C1C, 본문 #F5F5F5, 보조 #B3B3B3, 테두리 #333333, 강한 테두리 #666666.
- 앰버/노랑 강조색을 제거한다. 주요 버튼은 흰 바탕과 검정 글자, 보조 버튼은 무채색 테두리로 구분한다.
- 호버/선택/포커스는 무채색 대비와 밑줄/윤곽선으로 표시한다. 흰 버튼에는 어두운 간격을 둔 포커스 외곽선으로 구별한다.
- 헤더, 카드, 태그, 링크, 뷰어, 푸터, theme-color, 파비콘, 공유 이미지 등 사이트 자체 그래픽을 일관되게 정리한다.
- 프로젝트 이미지/영상의 고유 색은 보존한다. 작업물에 흑백 필터를 적용하지 않는다.
- 제목/본문 위계와 여백을 정돈하되 기존 정보 구조 및 반응형 기능을 유지한다.

### Google Sans
- 정확히 Google Sans를 사용한다. Google Sans Code나 Product Sans로 임의 대체하지 않는다.
- 공식 소스: https://github.com/googlefonts/googlesans (2026-10-04 확인: SIL OFL).
- 공식 배포본의 사용 가능한 폰트 파일을 확인하고 가급적 자체 호스팅한다. 출처와 배포 라이선스를 함께 보존한다. CSS 이름만 추가하고 설치된 폰트에 의존하지 않는다.
- 실제 파일의 한글 글리프 지원 여부를 확인한다. 미지원 한글은 Apple SD Gothic Neo, Malgun Gothic 등 기존 시스템 폰트로 대체하고 영문/숫자에 Google Sans를 적용한다.
- font-display: swap 및 필요한 굵기만 사용한다. 본문 400, 메뉴 500, 제목 600~700을 기준으로 실제 제공 굵기를 확인한다.
- 폰트 미설치 환경에서 실제 로드/영문 렌더링/한글 대체/로드 실패 시 가독성을 확인한다.

### 검증과 전달
- 기존 REQ-001 구현을 기반으로 진행하고 main 병합이나 외부 공개 배포는 하지 않는다.
- 320/390/768/1024/1440/1920px에서 메뉴, 제목, 카드 줄바꿈 및 가로 넘침을 확인한다.
- 대비, 키보드 초점, 44px 터치 영역, 200% 글자 확대 및 뷰어 동작을 확인한다.
- 타입 검사와 빌드를 실행하고 모바일/데스크톱 변경 후 스크린샷을 남긴다.
- STATUS.md의 REQ-001 기록을 보존하고 REQ-002 결과를 추가한다. 폰트 출처/라이선스/한글 처리/검증 결과/브랜치·커밋·PR을 기록한다.
- 요청 문서와 구현 결과를 함께 커밋·푸시하고 검토 가능한 PR로 남긴다.


## REQ-003: 영상 배경과 대형 타이포그래피의 메인 히어로
상태: 구현 대기
담당: Claude Code
사용자 방향(2026-10-04): 첨부한 크래프톤 메인 화면처럼 움직이는 배경 영상, 그 위의 볼드한 텍스트, 상단 메뉴바.
REQ-002(블랙·화이트, Google Sans)와 함께 적용한다. 참고 이미지는 채팅에만 있으므로 아래 서술을 구현 기준으로 사용한다.

### 참고 화면과 적용 범위
- 참고 화면: 검정 바탕에 전체 화면 배경 미디어, 상단 가로 내비게이션, 왼쪽 정렬된 매우 큰 3행 영문 제목, 제목 아래 작은 소개, 하단 스크롤 표시.
- 배치와 시각적 위계만 참고한다. 크래프톤 로고/문구/영상/브랜드 리소스를 가져오지 않는다. 빨강 타이포 대신 흰색을 사용한다.
- 기존 짧은 소개 영역을 첫 화면 히어로로 교체한다. 기존 프로젝트 목록, 상세 페이지, About/Contact, 확대 기능은 유지한다.
- 초기 PLAN의 작은 소개 및 영상 자동 재생 금지 규칙은 메인 장식용 무음 배경 영상에 한해 이 요청으로 대체한다. 상세 프로젝트 영상은 여전히 사용자 선택 재생이다.

### 데스크톱 구성
- 상단 왼쪽: 포트폴리오 이름/텍스트 로고. 오른쪽: Works, About, Contact. 미정 이름을 임의로 확정하지 않는다.
- 히어로 위 헤더는 투명한 검정 계열이며 흰 메뉴를 사용한다. 스크롤 후에는 불투명 검정 바탕으로 가독성을 확보한다.
- 히어로는 최소 100svh를 기본으로 하되 콘텐츠가 넘치면 높이가 늘어난다. 고정 높이와 overflow로 제목/버튼을 자르지 않는다.
- 배경 영상 위 검정 오버레이/그라디언트를 깔고 제목은 왼쪽 정렬한다. 영상이 밝은 장면에서도 글자를 읽을 수 있어야 한다.
- 임시 헤드라인: GAME UI / DESIGNED / FOR PLAY. 최종 확정 문구가 아닌 수정 가능한 기본안으로 데이터에 분리한다.
- Google Sans의 실제 지원 굵기 중 최대 700을 우선 사용한다. 가짜 굵기 대신 크기와 여백으로 볼드한 인상을 만든다.
- 제목은 데스크톱에서 약 clamp(4rem, 8.5vw, 10rem)을 출발점으로 실제 단어 폭에 맞춰 조정한다. 무조건 한 줄로 늘려 화면을 넘기지 않는다.
- 아래 소개 기본안: 플레이의 흐름을 만드는 게임 UI 디자이너. 작업물 보기 링크와 하단 스크롤 안내는 Works로 이동한다.
- 스크롤을 강제로 가로채거나 인트로 종료를 기다리게 하지 않는다. 프로젝트 목록은 히어로 바로 다음에 둔다.

### 모바일 구성
- 이름 + 메뉴 버튼. 메뉴 열림 상태에서는 배경 영상 위에서도 링크 대비와 초점을 보장한다.
- 제목을 2~3행으로 재배치하고 약 clamp(2.5rem, 11vw, 4.5rem)에서 실제 폭에 맞춰 조정한다. 320px에서도 긴 단어/버튼이 잘리지 않는다.
- 좁거나 낮은 가로 화면에서는 여백을 줄이고 콘텐츠 높이를 자연스럽게 늘린다. 200% 확대에서도 겹치지 않는다.
- 영상은 object-fit: cover를 사용하고 모바일용 파일/포스터/초점 위치를 데이터로 따로 설정할 수 있게 한다.
- 핵심 작업물 디테일을 배경 크롭에 의존하지 않는다. 세부 확인은 아래 프로젝트에서 제공한다.

### 배경 영상·접근성·성능
- hero 데이터: titleLines, description, videoDesktop, videoMobile(선택), posterDesktop, posterMobile(선택), focalPoint, ctaLabel/target.
- 사용자 보유 UI 모션 쇼릴을 최종 영상으로 받는다. 아직 파일이 없으므로 무채색 로컬 임시 포스터를 기본으로 제공하고 샘플임을 표시한다. 영상 경로를 넣으면 즉시 동작하는 구조까지 구현한다.
- 기존 자체 제작 샘플 영상이 이 연출에 적합하면 임시 영상으로 사용할 수 있으나 외부 영상을 무단 다운로드하거나 유료 생성 서비스를 사용하지 않는다.
- muted, loop, playsinline으로 무음 반복 재생한다. 자동 재생은 허용되는 환경에서 시도하고 실패하면 포스터를 유지한다. 재생 실패 때문에 페이지를 막지 않는다.
- 접근 가능한 일시정지/재생 버튼(44px 이상)을 항상 제공한다. 사용자가 멈춘 상태는 화면 재진입 시에도 유지한다.
- prefers-reduced-motion 또는 지원되는 데이터 절약 설정에서는 처음부터 영상을 요청/자동 재생하지 않고 포스터를 표시한다. 사용자의 명시적 재생 선택은 허용한다.
- 히어로가 화면 밖이거나 탭이 숨겨지면 재생을 멈춘다. 돌아올 때는 사용자의 정지 의사를 존중한다.
- 영상은 장식용으로 처리하고 제목·설명은 실제 HTML 텍스트로 제공한다. 빠른 섬광이나 과도한 움직임은 피한다.
- 영상보다 포스터와 텍스트를 먼저 표시한다. 모바일/PC 영상을 둘 다 다운로드하지 않는다. 최종 영상은 짧은 8~15초 루프, 모바일 약 3MB/PC 약 6MB 이내를 권장 목표로 하되 실제 제공 파일에 맞춰 최적화한다.
- 영상이 없는 현재 상태를 명확히 기록하고 실제 영상 교체 경로/포스터 제작 규격을 README에 안내한다.

### 검증과 결과
- 320/390/768/1024/1440/1920px, 모바일 가로 화면, 200% 글자 확대에서 제목·메뉴·CTA가 겹치거나 잘리지 않는지 확인한다.
- 자동 재생 차단, 영상 파일 없음/로드 실패, 모션 줄이기, 사용자 일시정지, 화면 밖 정지, 모바일 메뉴 및 Works 이동을 확인한다.
- 기존 반응형 카드/상세/이미지 확대가 유지되는지 확인하고 타입 검사·빌드를 실행한다.
- STATUS.md에 REQ-003 결과 및 실제 영상 여부/미검증 항목을 기록하고 모바일·데스크톱 스크린샷을 남긴다.
- 구현 코드와 요청 문서를 함께 커밋·푸시하고 검토용 PR로 남긴다. main 병합·외부 배포는 하지 않는다.


### REQ-003 확정 보완: 기존 샘플 영상 우선 적용 (2026-10-04)
사용자 요청: 별도 영상 제작 전에 샘플을 먼저 넣는다. 이 보완 사항은 위의 영상 미정/포스터 우선 구현 기준보다 우선한다.
- 신규 영상 제작·구매·AI 생성은 하지 않는다. 이미 저장소에 있는 public/videos/rpg-hud-interaction.webm(약 253KiB)을 메인 히어로 배경으로 실제 연결한다.
- 기본 desktop/mobile 소스는 같은 파일로 설정한다. BASE_PATH를 반영한 URL로 로드한다.
- 이 영상은 최종 흑백 UI 모션이 아닌 기존 RPG UI 임시 샘플이다. 최종 영상처럼 설명하지 말고 작게 SAMPLE VIDEO로 표시한다.
- 히어로 배경에 한해서 CSS grayscale(1)과 검정 오버레이로 흑백 컨셉 및 흰 제목 가독성을 맞춘다. 프로젝트 상세의 원본 영상과 이미지는 그대로 유지한다.
- 기존 RPG 프로젝트의 로컬 포스터 이미지를 재사용하고 재생 불가/모션 줄이기 환경에서는 포스터를 표시한다. 실제 영상 파일은 수정하지 않는다.
- muted/loop/playsinline, 재생·일시정지 버튼, 화면 밖 정지 등 앞의 요구사항은 유지한다.
- 본인의 최종 영상은 나중에 hero 데이터의 파일 경로만 교체할 수 있게 한다.
- 메인 히어로 대형 제목에만 Zalando Sans Expanded 700~900 중 적절한 굵기를 사용한다. 메뉴·본문은 Google Sans를 유지한다. REQ-002/003의 모든 제목을 Google Sans로 지정한 기준보다 이 역할 구분이 우선한다.
- Zalando Sans Expanded는 Google Fonts 공식 배포본을 사용하고 OFL 라이선스를 보존한다. 출처: https://fonts.google.com/specimen/Zalando+Sans+Expanded / https://github.com/google/fonts/tree/main/ofl/zalandosansexpanded
- 메인 배경 영상이 실제로 로드·반복 재생되는지와 정지 버튼을 확인한다. 화면만 구현하고 정지 이미지로 남겨두지 않는다. 재생 제약이 있는 브라우저는 포스터 대체 여부를 기록한다.

### 3. 상단 내비게이션·버튼
- 좌측 이름, 우측 커스텀 3선 메뉴 버튼을 모든 화면에서 제공한다. 현재 펼쳐진 데스크톱 Works/About/Contact 텍스트 메뉴는 이 전체 화면 메뉴로 대체한다.
- 선은 가늘고 길이가 다른 형태, 무채색. hover/focus 때 길이와 정렬이 150~200ms로 정돈되며 열릴 때 닫기 X로 전환한다.
- 버튼 영역 최소 44×44px. 상태에 따른 메뉴 열기/닫기 이름, aria-expanded, aria-controls를 제공한다.
- 퍼셉트의 중앙 캡슐 메뉴까지 동시에 추가하지 않는다. 3개 항목인 개인 포트폴리오에서 내비게이션 중복을 줄인다.

### 4. 전체 화면 메뉴와 열림/닫힘
- 페이지 위 전체 화면 오버레이로 열고, 뒷 화면은 무채색 어둡게 + 가벼운 블러로 처리한다. 블러 미지원 시 불투명 검정으로도 충분히 읽히게 한다.
- 메뉴: Works / About / Contact 세 항목만 큰 글자로 표시한다. 없는 Board/IR 등은 만들지 않는다.
- PC는 왼쪽에 큰 메뉴, 오른쪽에 간단한 직무 소개와 실제 값이 있는 연락처/외부 링크만 배치한다. 임시 연락처를 실제 주소처럼 노출하지 않는다. 값이 없으면 보조 칼럼을 비운다.
- 모바일은 단일 열, 넉넉한 간격. 메뉴 내용이 화면보다 높으면 메뉴 내부만 스크롤하고 닫기 버튼은 항상 접근 가능하게 한다. 세이프 영역을 반영한다.
- 제안 모션: 배경 감광/블러 200~300ms → 메뉴 항목이 20~30px 아래에서 올라오며 opacity 0→1, 각 항목 60~80ms 간격, 전체 450~600ms.
- 닫기 200~300ms로 짧게. 빠른 연속 클릭/열림 도중 Escape에도 최종 상태가 맞고 잠금·초점이 남지 않게 한다.
- 모달 접근성: 열 때 배경 inert와 스크롤 잠금, 내부 초점 이동/순환, Escape와 닫기 버튼 지원, 닫을 때 기존 스크롤/버튼 초점 복원.
- 메뉴 앵커 선택 시 오버레이를 닫고 목적지로 이동한다. 이때는 트리거로 초점을 되돌리지 말고 목적지 제목에 초점을 주어야 한다. 상세에서도 메인의 해당 앵커로 이동한다.
- 메뉴 열린 동안 배경 영상은 임시 정지하고 닫힌 뒤에는 사용자 재생 의사·모션 줄이기·화면 가시성에 따라 복원한다. 자동 정지를 사용자의 영구 정지 선택으로 저장하지 않는다.

### 5. 접근성·모션·성능·기존 요청과 우선순위
- prefers-reduced-motion에서는 입장 연출과 반복 모션을 생략하고 메뉴도 즉시 또는 짧은 페이드만 사용한다. 메뉴 기능 자체는 유지한다.
- CSS transform/opacity 중심으로 구현한다. 기존 기술로 가능한 모션 때문에 대형 애니메이션/3D 라이브러리를 새로 추가하지 않는다.
- 입장 애니메이션이 200% 글자 확대, 줄바꿈, 키보드 접근, 모바일 가로 화면을 깨지 않게 한다.
- 이 요청은 이전 정적/모바일 전용 메뉴 구성을 대체한다. REQ-004 정지 버튼·헤드라인 언어 구조와 REQ-005 영상 선택은 유지한다.
- 프로젝트 목록의 대규모 스크롤 연출, 커스텀 커서, 신규 로고/3D 자산, 사이트 전체 리디자인은 제외한다.

### 검증과 전달
- 첫 방문/같은 탭 재방문/앵커 직접 진입/뒤로가기, JS·영상 실패와 모션 줄이기를 검사한다.
- 메뉴 열림/닫힘/연속 클릭/Escape/Tab 순환/초점 복원/앵커 선택/스크롤 잠금 해제를 검사한다.
- 320/390/768/1440/1920px 및 667×375/844×390, 글자 200%에서 메뉴·닫기·영상 제어 접근을 확인한다.
- 타입 검사·빌드와 변경 관련 회귀 검사를 실행하고 STATUS.md에 결과/가정/미검증을 기록한다.
- 입장과 메뉴 열림/닫힘은 정지 이미지로만 판단하지 않도록 5~10초 화면 녹화 또는 시간 순서 캡처를 함께 남긴다. 모바일/PC 메뉴 최종 상태 스크린샷도 제공한다.
- 현재 다른 작업의 미커밋 변경을 보존한다. REQ-004/005 완료 또는 변경 조율 후 별도 커밋/검토 PR로 진행한다. main 자동 병합/공개 배포는 하지 않는다.


## REQ-007: Odyssey 포스터 블루 키컬러와 SCROLL DOWN 지속 루프
상태: 구현 대기
담당: Claude Code
사용자 요청(2026-10-04): 첨부한 영화 The Odyssey 포스터의 블루를 홈페이지 전반의 키컬러로 사용하고, PERCEPT처럼 SCROLL DOWN 루프 애니메이션을 적용한다.
이 요청은 REQ-002의 무채색 전용 강조 규칙과 REQ-006의 SCROLL DOWN 3회 반복 후 정지 규칙을 대체한다. REQ-004 접근성과 REVIEW-PR-003-004의 R1/R2는 보존한다.

### 색상 방향과 적용
- 검정 배경·흰색 본문을 바탕으로, 채도가 낮은 스틸/오션 블루를 사이트 공통 강조색으로 사용한다. 포스터의 빨간 날짜 색은 도입하지 않는다.
- 초기 제안 토큰: accent #2D5973, accent-readable #78A9C6, accent-surface #102532. 첨부 이미지의 인상을 보고 제안한 근사값이며 픽셀 추출값이나 영화 공식 브랜드 색상이 아니다.
- accent는 주요 CTA의 바탕과 장식 면, accent-readable은 검정 배경 위 작은 링크·아이콘·포커스·기능성 선에 사용한다. CTA 텍스트는 흰색으로 유지한다. 실제 배경 및 hover/focus 상태별 대비를 검증하고 필요하면 동일 계열에서 조정한다.
- 첫 적용안: 히어로 제목의 FOR PLAY 행은 밝은 블루, 나머지 두 행은 흰색. 제목 문구가 교체될 때 특정 문자열에 하드코딩하지 말고 강조 행을 데이터로 선택할 수 있게 한다. 기존 lang/soft hyphen/글자 확대를 보존한다.
- 입장 화면의 이름, SCROLL DOWN의 이동 선, 메뉴 버튼 hover/focus 및 열린 메뉴의 hover/focus 항목·번호, Works/About/Contact 섹션 라벨, 링크·주요 버튼·카드 hover/focus에 공통 토큰을 적용한다.
- 열린 메뉴 기본 항목은 흰색, 배경은 기존 어두운 블러를 유지한다. 페이지 전체를 파란 면으로 덮지 않고 핵심 동작과 강조에 일관되게 배분한다.
- 상세 페이지의 링크·버튼·포커스에도 동일 규칙을 적용한다. 프로젝트 원본 이미지/영상에 블루 필터를 씌우지 않는다. 히어로 영상의 기존 흑백 규칙은 별도 변경 요청 전까지 유지한다.
- 색만으로 상태를 구분하지 않도록 밑줄·외곽선 등 기존 상태 표시를 유지한다. 초점 외곽선은 흰 CTA와 어두운 바탕 양쪽에서 구별되게 한다.
- Google Sans/히어로 Zalando Sans Expanded 및 기존 글꼴 라이선스는 유지한다.

### SCROLL DOWN 루프
- 왼쪽 아래 세로 트랙 + SCROLL/DOWN 2행 구조 유지. 텍스트는 고정하고 짧은 블루 선만 위→아래로 이동·페이드한다.
- 약 1.8초 주기의 연속 반복으로 바꾼다. 3회 후 자동 종료하지 않는다.
- 히어로가 화면 밖이거나 탭이 숨겨졌거나 전체 화면 메뉴가 열리면 중지한다. 다시 보이면 사용자 정지 의사를 존중해 재개한다.
- prefers-reduced-motion에서는 반복하지 않고 정적 표시한다.
- 계속 움직이는 장식을 멈출 수 있도록 기존 영상 재생/정지 제어와 연동한다. 정지를 누르면 영상과 스크롤 선을 함께 멈추고, 버튼의 접근 가능한 이름도 제어 범위를 설명한다. 기존 영상 정지 저장 및 메뉴 임시 정지를 구분한다.
- 영상 로드 실패/포스터 상태에도 스크롤 루프만 계속 켜진 채 정지 수단이 사라지지 않게 한다. 영상과 장식 모션 상태를 별도로 관리하되 사용자에게는 간단한 배경 모션 제어로 제공할 수 있다.
- Works 앵커, 44px 터치 영역, 키보드 초점, 일반 스크롤 동작을 유지한다.

### 구현과 검증
- 현재 진행 중인 PR #4 R1/R2 수정 및 미커밋 변경을 보존한다. 최신 브랜치 상태를 확인하고 별도 커밋으로 구분한다. main 자동 병합·공개 배포는 하지 않는다.
- REQ-005 4Ground9 영상 교체와 별개이며, 현재 RPG 샘플을 실제 영상으로 완료 처리하지 않는다.
- 데스크톱/모바일 메인·메뉴·프로젝트 상세의 기본/hover/focus 화면을 남긴다. R2의 넓은 화면 정렬을 보존한다.
- 루프가 3회를 넘어서도 지속되는 8~10초 이상 녹화와 사용자 정지/화면 밖/탭 숨김/메뉴/reduced-motion 확인 결과를 남긴다.
- 320/390px, 667×375/844×390, 1440/1920/2560px 및 글자200%에서 가독성·제어 접근을 확인한다.
- 타입 검사·빌드 및 변경 관련 회귀 검사. STATUS에 최종 토큰값, 적용 위치, 동작, 검증/미검증과 커밋/PR을 기록한다.
