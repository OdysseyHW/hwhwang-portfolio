# 게임 UI 디자이너 포트폴리오 구현 명세
작성일: 2026-10-04 (Asia/Seoul). 상태: 기본 틀 구현용 초안.

## 역할과 목표
GPT/Codex는 기획·검토, Claude Code는 구현·검증을 담당한다.
대표 작업물 → 담당 역할 → 디자인 의도와 과정 → 연락처 순서로 쉽게 탐색하게 한다.
사용자 지시가 이 문서보다 우선한다. 실제 콘텐츠와 최종 테마는 미확정이다.

## 범위와 기술
메인, 재사용 가능한 프로젝트 상세, 샘플 프로젝트 3개, 이미지 확대 뷰어, 404, 전체 반응형 대응을 구현한다.
로그인, 관리자, DB, 결제, 자체 문의 서버, 검색/필터는 초기 범위에서 제외한다.
유료 서비스·소재·API는 사용하지 않는다. 웹사이트 외부 공개 배포는 별도 사용자 요청 후 진행한다.
기존 지침과 파일을 먼저 확인하고 미커밋 변경을 보존한다.
기존 구현이 없다면 Astro + TypeScript, CSS 변수, 정적 빌드를 기본으로 한다. 불필요한 의존성은 추가하지 않는다.
GitHub Pages 등 정적 호스팅에 대응하고 루트/하위 경로의 링크와 이미지, 상세 주소 직접 접속·새로고침을 지원한다.
진행 가능한 미정 사항은 기본값으로 구현하고 STATUS.md에 기록한다.

## 기본 디자인
변경 가능한 기본값: 절제된 다크 갤러리, 짙은 무채색 배경, 밝은 본문, 강조색 한 가지, 한글 시스템 폰트.
색상·폰트·여백·테두리·콘텐츠 폭은 토큰으로 관리한다.
작업물을 우선하며 과도한 네온, 장식 HUD, 커스텀 커서, 파티클, 긴 인트로는 제외한다.
테마 전환 기능은 초기 범위에서 제외한다.

## 페이지 구성
- / : 메인
- /projects/[slug]/ : 프로젝트 상세
- 404 : 없는 주소 안내와 메인 복귀

메인: 이름/로고와 메뉴 → 직무·짧은 소개·작업물 보기 → 대표 프로젝트 3개 → About → Contact → 푸터.
Works/About/Contact는 메인 해당 영역으로 이동한다. 상세 페이지에서도 정상 동작한다.
카드에는 이미지, 제목, 프로젝트 유형, 플랫폼, 담당 분야를 표시한다.
카드 전체를 명확한 링크로 만들고 중첩 링크를 피한다. 호버 없이도 핵심 정보가 보인다.
첫 화면을 거대한 소개로 채우지 않고 작업물에 빠르게 도달하게 한다.

상세 순서:
1. 제목, 한 줄 설명, 대표 이미지
2. 장르, 플랫폼, 기간, 개인/팀 작업 여부
3. 담당 역할·직접 제작 범위
4. 디자인 목표·해결하려던 문제
5. UX 흐름·정보 구조·와이어프레임
6. 최종 UI·컴포넌트
7. 선택적 인터랙션 영상
8. 결과·회고
9. 목록 및 이전/다음 프로젝트
없는 선택 항목은 빈 제목 없이 숨긴다. 전체 이미지와 세부 이미지·캡션을 함께 배치할 수 있게 한다.

## 반응형 UX
기기 감지 없이 모바일 우선 유동 레이아웃을 구현한다. 기본 기준:
- 320~599px: 카드 1열, 세로 구성, 좌우 여백 약 16px
- 600~899px: 카드 1~2열, 최소 카드 너비 부족 시 1열 유지
- 900~1199px: 카드 2열, 전체 메뉴와 개요 가로 배치 가능
- 1200px 이상: 카드 3열, 최대 콘텐츠 폭 약 1280px, 중앙 정렬

중간 너비에서도 자연스럽게 대응한다. 본문 가로 넘침, 겹침, 잘림이 없어야 한다.
긴 한글 제목·영문 단어·URL도 대응한다.
본문 기본 16px 이상, 글 영역 약 65ch 이내. 제목과 여백은 clamp 등으로 유동 조절한다.
고정 높이로 글을 자르지 않는다. 주요 터치 영역은 최소 44×44px을 목표로 한다.
회전, 브라우저 200% 확대, 글자 확대에서도 정보와 기능을 유지한다.
고정 헤더 사용 시 앵커 제목이 가려지지 않게 한다. 모바일에서 핵심 기능·정보를 숨기지 않는다.
공간 부족 시 모바일 메뉴로 전환하며 열림 상태, 닫기, Escape, 초점 처리를 지원한다.

## 이미지 확대
상세 이미지는 원본 비율을 보존한다. 썸네일에만 자르기를 허용하고 이미지별 중심 위치를 지정한다.
모바일에서 PC 게임 UI 세부 내용을 볼 수 있도록 전체 화면과 확대 영역 자료를 함께 지원한다.
이미지 선택 시 뷰어를 열고 화면 맞춤, 확대/축소 버튼, 확대 이미지 이동, 원본 링크를 제공한다.
터치·마우스 모두 지원하고 핀치에만 의존하지 않는다.
닫기 버튼, Escape, 내부 초점 관리, 배경 스크롤 잠금, 닫힌 후 초점·스크롤 복원을 구현한다.
브라우저 기본 확대를 막지 않는다.

## 데이터 구조와 샘플
콘텐츠를 코드와 분리하고 타입/스키마를 적용한다.
프로젝트 필드: slug, title, summary, projectType, genre, platform, period, teamType, roles[], contribution, coverImage, coverAlt, coverPosition(선택), tags[], featured, order, sections[].
sections는 제목, 본문, 이미지/대체 설명/캡션, 선택적 영상을 지원한다.
공통 정보: name, jobTitle, intro, about, skills[], email, socialLinks[], resumeUrl(선택).
없는 연락처/링크/이력서 버튼은 숨긴다. 데이터 추가 시 목록·상세가 함께 생성되게 한다.

샘플 3개: RPG HUD·캐릭터 정보 / 모바일 로비·메뉴 UX / 인벤토리·상점 UI.
샘플 표시를 명확히 하고 자체 제작 SVG/도형 이미지를 사용한다.
상용 게임 이미지를 무단 수집하지 않는다. 실제 경력·회사·성과·기여도를 임의로 만들지 않는다.

## 접근성·성능·검색
시맨틱 HTML, 제목 계층, 본문 바로가기, 키보드 탐색, 초점 표시, 대체 설명, 아이콘 버튼 이름을 적용한다.
일반 텍스트 대비 4.5:1 이상 목표. prefers-reduced-motion 반영. 영상 자동 재생 금지.
적절한 이미지 크기/포맷, width/height 지정으로 레이아웃 이동 방지.
첫 화면 핵심 이미지는 지연 로딩하지 않고 하단 이미지는 지연 로딩한다.
영상은 포스터 우선, 필요 시 로드. 외부 폰트·JS·라이브러리를 최소화한다.
페이지별 title/description/Open Graph와 파비콘을 제공한다.
실제 배포 주소 확정 후 canonical/sitemap 적용 가능하게 하고 가짜 주소를 하드코딩하지 않는다.

## 검증 기준
너비 320/375/390/600/768/900/1024/1199/1200/1440/1920px 및 사이 너비를 확인한다.
- 본문 넘침·겹침·잘림 없음
- 모바일 메뉴, 카드 이동, 상세 직접 접속·새로고침
- 이미지 비율, 확대/이동/닫기, Escape, 키보드 초점 및 복원
- 200% 확대와 모바일 가로 화면
- 긴 제목, 선택 필드가 없는 데이터
- 깨진 이미지/링크 및 콘솔 오류 없음
- 정적 빌드 성공
가능한 Chromium/Firefox/WebKit에서 확인한다. 실제 모바일과 에뮬레이션을 구분한다.
실제 측정한 결과만 기록하고 확인 못한 항목은 미검증으로 보고한다.
